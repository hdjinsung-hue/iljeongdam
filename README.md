# 일정담

음성·문장·일정 파일에서 날짜와 제목을 추출하고 확인한 일정을 휴대폰 캘린더로 가져오는 반응형 정적 웹앱입니다. 기존 합의금 앱과 분리된 독립 프로젝트입니다.

## 실행

저장소 루트에서 다음을 실행하고 `/` 경로를 여세요.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

HTML·CSS·JavaScript 기반이며 Node 빌드나 서버 DB가 필요하지 않습니다. 기본 초안 기능은 계정 없이 사용하고, Google 동기화에는 별도의 웹 OAuth 클라이언트 ID 설정이 필요합니다. OCR·PDF 라이브러리와 언어 모델은 `vendor/`에 포함했습니다. ES 모듈과 워커를 사용하므로 HTML 파일을 더블클릭하는 대신 HTTP 서버를 이용하세요.

## 사용

1. 사진 촬영 또는 파일 선택: JPG·PNG·WEBP·PDF·Excel XLSX·Word DOCX·UTF-8 TXT·CSV·ICS.
2. 사진·PDF·Excel·Word·TXT는 인식 내용을 확인하고 **내용에서 일정 찾기**를 누르세요. CSV·ICS는 일정 목록에 바로 추가합니다.
3. 날짜·시간·제목·장소를 수정하고 가져올 일정을 선택하세요. 제목 누락, 잘못된 날짜, 종료 시간이 시작보다 빠르면 내보내기를 막습니다.
4. **캘린더 파일 다운로드** 또는 지원 브라우저의 **휴대폰 캘린더로 공유**를 사용하세요.
5. 캘린더 앱에서 최종 추가를 완료하세요.

예시:

```text
2026-11-12 10:00~11:00 팀 주간회의
2026년 11월 13일 오후 2시 건강검진
11/15 가족 모임
```

한 줄에 일정 하나를 입력합니다. 날짜만 있는 줄 아래의 일정은 그 날짜를 사용합니다. 연도가 없으면 화면의 기준 연도를 적용하고 알려줍니다. 종료 시간이 없으면 1시간 후로 제안하며, 시간이 없으면 종일 일정입니다. 자정을 넘는 일정은 직접 추가에서 종료일을 수정하세요.

CSV는 첫 행에 `날짜,시작,종료,제목,장소`를 넣습니다. 필수 열은 날짜·제목이고 날짜는 `YYYY-MM-DD`, 시간은 `HH:mm`입니다. 쉼표를 포함한 제목은 큰따옴표로 감싸세요.

## 휴대폰 캘린더 연결 범위

GitHub Pages의 일반 웹앱은 기기의 애플·삼성 캘린더에 사용자 승인 없이 직접 기록할 수 없습니다. 이 앱은 표준 ICS 파일과 지원 기기의 파일 공유 기능으로 가져오기를 연결합니다. 로그인 기반 Google Calendar API 자동 동기화는 포함하지 않습니다.

- 아이폰: 지원 앱에서 .ics를 열고 추가하세요. iOS 버전에 따라 파일 앱에서 바로 가져올 수 없으므로 지원되는 메일 앱의 첨부파일로 여는 방법이 필요할 수 있습니다. 공유 목록에 캘린더가 항상 표시되는 것은 아닙니다.
- 안드로이드: .ics 파일 열기를 지원하는 캘린더 앱으로 가져오세요. Google Calendar 모바일 앱에서 파일 가져오기가 안 되면 PC 웹의 설정 → 가져오기/내보내기를 사용하세요. 동일 계정의 휴대폰에 동기화됩니다.
- 시간은 현재 기기 시간대로 해석하며, 시간 일정은 UTC로 내보내고 종일 일정은 날짜 그대로 내보냅니다. 원본 ICS의 UTC·기기와 같은 TZID·floating 시간을 지원합니다. 다른 TZID와 반복 일정은 오류 안내 후 건너뜁니다.
- 앱 내 중복 가져오기는 제외하지만, 캘린더 앱에서 동일 ICS를 여러 번 가져올 때 중복 방지는 보장하지 않습니다.

## 지원과 제한

- 파일 1개 최대 15MB, 한 번에 최대 10개, PDF 최대 20쪽, 일정 최대 300개.
- HEIC는 JPG·PNG로 변환하세요. 구형 .xls·.doc는 Excel·Word에서 .xlsx·.docx로 다시 저장하세요. 암호가 걸린 문서는 지원하지 않습니다.
- OCR은 인쇄된 한국어·영어에 맞췄습니다. 월간 달력 표는 요일과 날짜 칸의 위치를 연결합니다. 날짜 숫자와 요일을 충분히 읽지 못하면 임의로 일정을 만들지 않습니다. 손글씨·불규칙한 표·작은 글씨는 오인식할 수 있으므로 결과를 확인하세요.
- 파일과 문서는 외부 서버로 보내지 않습니다. 확인 중인 일정만 해당 사이트의 브라우저 localStorage에 저장합니다. 원본 이미지와 인식 텍스트는 새로고침 후 보존하지 않습니다. 저장 차단 시 경고합니다.
- 앱 외부의 다른 웹앱과 브라우저 동작은 검증 범위에 포함하지 않습니다.

## GitHub Pages 배포

저장소의 `.github/workflows/pages.yml`이 일정담 앱을 배포합니다.

1. 새 파일들을 저장소의 `main` 브랜치에 커밋·푸시합니다.
2. GitHub 저장소 **Settings → Pages → Source → GitHub Actions**를 선택합니다.
3. **Actions → Deploy static apps to GitHub Pages** 실행 결과를 확인합니다. 필요하면 **Run workflow**로 실행하세요.
4. 배포가 완료되면 `https://hdjinsung-hue.github.io/iljeongdam/`에서 새 앱을 엽니다. 이 주소는 배포 후 예상 경로이며, 현재 배포 완료를 의미하지 않습니다.

모든 자산 경로는 상대 경로여서 저장소 하위 경로에서도 동작합니다. 워크플로는 테스트·문서 전체나 Git 메타데이터를 별도 업로드하지 않고 공개 앱 파일만 모읍니다. 배포 설정과 코드는 저장소에 포함되어 있습니다. main에 푸시하면 Pages 워크플로가 실행됩니다.

```sh

```

단위 테스트에는 Node.js 22 이상을 권장합니다. 브라우저 테스트는 Python의 `playwright`와 `/usr/bin/chromium`을 사용합니다. 문서 통합 테스트의 원본 생성에는 Python `openpyxl`과 `python-docx`를 사용합니다. 이 클라우드 환경에는 이미 설치되어 있습니다. 로컬 소켓·브라우저 실행 권한이 필요합니다.

- 단위 테스트 8개: 한국어 시간·종일·잘못된 날짜/시간·중복·CSV·ICS 이스케이프/UTF-8 줄 접기·종일 종료일·반복/시간대 제한.
- Chromium: 파일 입력, 수정, 삭제, 선택, 자동 저장 복원, 다운로드/다시 가져오기, 잘못된 입력, HTML 문자열 안전 표시, 320·375·390·768·1280px 가로 넘침 검사.
- 실제 한국어 사진 OCR, 스캔 PDF OCR, 텍스트 PDF 추출, 인식 취소 후 다시 가져오기.
- 달력 위치 연결 단위 테스트 8개 및 실제 XLSX·DOCX 일반 표/달력 표, 달력 사진, 텍스트 달력 PDF, 선택 가능한 제목을 가진 스캔 PDF, 연월 지정 후 재인식, 손상 문서와 구형 형식 오류 처리.
- 실제 아이폰 Safari·안드로이드 캘린더 앱과 GitHub Actions 배포는 아직 실행하지 않았습니다. 물리 기기의 카메라·공유·최종 캘린더 추가는 추가 확인이 필요합니다.

## v2.0: 달력 표와 Office 파일

- Excel `.xlsx`: 날짜·제목·시작·종료 열을 구분하고 날짜/시간 셀의 실제 값을 읽습니다. 보이는 시트를 각각 처리하며 병합된 셀의 복사 값을 중복 일정으로 만들지 않습니다. 수식은 문서에 저장된 결과만 읽고 실행하지 않습니다.
- Word `.docx`: 본문·표·셀 안의 줄바꿈을 유지합니다. 문서에서 만들어진 HTML은 화면에 삽입하지 않습니다. 문서 안의 그림은 인식하지 않으므로 별도의 사진으로 저장해 넣으세요.
- PDF: 선택 가능한 글자의 위치를 이용해 달력 칸을 연결합니다. 스캔 페이지는 OCR로 읽고, 선택 가능한 제목이 있는 스캔 문서도 다시 검사합니다.
- 사진: 글자 위치를 보존하고 작은 사진은 확대해 인식합니다. 기본은 자동 구분이며, 잘 안 읽히면 “달력 표”와 “달력의 연월”·“첫 요일”을 선택한 뒤 **선택한 파일 다시 읽기**를 누르세요. 인식한 원본 파일은 해당 화면이 열린 동안만 메모리에 둡니다.
- 문서에 연월이 없으면 현재 월을 추측하지 않습니다. 실제 달력의 연월을 입력해야 합니다. 날짜와 요일이 맞지 않는 칸도 제외하고 안내합니다.
- Office 압축 해제 전 파일 수·선언된 크기를 제한합니다. 시트 최대 30개, 시트당 10,000행·100열, 압축 해제 크기 100MB가 상한입니다. 파일당 15MB 제한도 적용합니다.
- 이 테스트는 생성한 대표 문서로 검증한 결과입니다. 사용자의 원본 일정표는 전달받지 않아 동일 문서에서의 정확도는 아직 확인하지 않았습니다.

## v2.1: 손글씨 달력의 칸별 확인

한글 손글씨의 자동 OCR 정확도를 보장하지 않습니다. 손글씨를 잘못 읽는 사진은 **손글씨 달력: 사진 영역 지정하고 칸별 확인**을 사용하세요.

1. 이 메뉴에서 사진을 선택합니다. 원본은 브라우저 메모리에서만 처리합니다.
2. 실제 달력의 **연월·첫 요일·날짜 칸 줄 수**를 확인합니다. 연도가 없으면 사용자가 선택해야 합니다.
3. 날짜 칸 표의 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래를 차례대로 누릅니다. 요일 제목은 제외하며, 앞뒤의 빈 날짜 칸은 포함합니다.
4. **날짜별 칸 펼치기**를 누르면 원근을 보정한 칸 사진과 날짜가 표시됩니다. 이 날짜는 작은 날짜 숫자의 OCR 대신 선택한 연월과 칸 위치로 계산하므로, 모서리·줄 수·첫 요일을 잘못 지정하면 날짜도 달라집니다.
5. **칸별 문자 읽기**로 제목·시간 후보를 얻거나 사진을 보고 직접 입력하세요. OCR은 자동으로 일정을 선택하지 않습니다.
6. 사진과 내용을 확인한 날짜에만 **확인 완료**를 체크하고 **확인한 일정만 목록에 추가**를 누릅니다. 제목이 비어 있으면 추가하지 않습니다. 시간이 없으면 종일로 표시합니다. 시간이 있으면 종료는 1시간 후로 제안되므로 원래 일정에 맞춰 수정하세요.

각 칸에 일정이 여러 개면 기존 **직접 추가**에서 개별 일정으로 입력하세요. 새 메뉴의 사진·모서리·입력 중인 내용은 새로고침 후 복원되지 않습니다. 최종 목록에 추가한 일정만 기존 자동 저장 대상입니다.

추가 검증:

```sh
node tests/photo-grid.test.mjs
python3 tests/photo-review.py
```

사각형 원근 좌표, 일요일/월요일 시작, 5·6주 달력, 잘못된 연월, 제목 누락, OCR 후보 미선택, 확인한 일정만 추가, 모바일 가로 넘침을 검사했습니다. 브라우저 테스트의 이미지는 생성한 표이며 사용자가 첨부한 손글씨 원본의 OCR 성공을 증명하지 않습니다. 별도로 사람이 판독한 사용자 일정 초안은 공개 저장소에 넣지 않습니다.

## v3.0: 말로 일정 만들기

첫 화면에서 **음성 입력 시작** → “내일 오후 3시 병원 예약” → **말하기 완료** 순서로 이용합니다. 브라우저가 음성 인식을 제공하면 인식된 문장을 자동으로 일정 초안으로 바꿉니다. 마이크 권한과 HTTPS가 필요합니다. 지원하지 않는 브라우저·권한 거부·서비스 연결 오류에서는 입력칸을 누르고 휴대폰 키보드의 마이크로 받아쓰기한 뒤 **말한 내용으로 일정 만들기**를 누르세요.

- 지원 표현: 오늘·내일·모레, 이번/다음/다다음 주 요일, “11월 12일”, “2026년 11월 12일”, 오전·오후, “세 시 반”, “10시 30분”, `10:30`, 시작~종료 시간.
- “오늘·내일의 기준 날짜”는 기기 현지 날짜로 시작하며 수정할 수 있습니다. 연도가 없는 월일은 그 기준 날짜의 연도를 적용합니다. 자동으로 내년을 추측하지 않습니다.
- 여러 일정은 날짜를 각각 말하세요. 날짜를 읽지 못하면 임의로 오늘에 추가하지 않습니다. 시간이 없으면 종일, 종료가 없으면 1시간 후로 제안합니다. 오전·오후를 생략한 시간은 확인 안내를 표시합니다.
- 인식한 문장과 일정 초안을 확인하세요. 웹 음성 인식의 실제 정확도는 휴대폰·브라우저·소음·발음·인식 서비스에 따라 달라집니다. 방언·임의의 자연어·반복 일정·복잡한 기간을 모두 이해하는 모델은 아닙니다.
- 일정 카드의 **Google 캘린더로 열기**는 로그인된 Google Calendar의 작성 화면을 엽니다. 사용자가 **저장**해야 등록됩니다. 애플·삼성 캘린더에는 기존 ICS 가져오기/지원 기기의 공유를 사용합니다.
- 휴대폰 기본 달력에 직접 등록하려면 Siri 또는 기기의 연결된 캘린더를 지원하는 Gemini 등 음성비서를 사용할 수 있습니다. 예: “캘린더에 내일 오후 3시 병원 예약 추가해 줘.” 계정 연결·캘린더 권한 및 기기에서 제시하는 확인이 필요합니다. 이 앱이 해당 비서를 호출하거나 등록 완료 여부를 확인하지는 않습니다.
- 사진·문서 처리는 기존대로 기기 안에서 수행합니다. **음성은 브라우저·기기의 인식 서비스로 전송될 수 있습니다.** 앱은 마이크를 자동으로 켜지 않으며 시작 버튼 후에만 듣고, 중지·취소를 제공합니다. 음성 파일을 앱 서버에 저장하는 기능은 없습니다. 완성한 일정은 기존처럼 브라우저에 저장됩니다.
- 사진·문서 기능은 **사진·문서에서 일정 가져오기** 보조 메뉴에 보존되어 있습니다.

## v4.0: 모바일 앱 화면·Google 연동·잠금화면 안내

- 휴대폰 화면에는 큰 음성 시작 버튼과 고정 하단 마이크가 표시됩니다. 잠금화면이나 앱 시작 시 마이크를 자동으로 켜지 않습니다. 웹 음성 인식 미지원 기기에서는 하단 버튼이 받아쓰기 입력칸을 엽니다.
- ‘오늘의 일정’은 현재 기기 날짜에 해당하는 일정과 초안/Google 등록/수정 대기 상태를 보여줍니다.
- 홈 화면 설치용 웹 앱 매니페스트, 아이콘, 서비스 워커를 제공합니다. 아이폰은 Safari 공유 → 홈 화면에 추가, 안드로이드는 지원 브라우저의 앱 설치를 사용합니다. 설치 안내는 화면 하단에 있습니다.
- 오프라인에서는 이미 설치된 앱 화면과 수동 문장 초안을 사용할 수 있습니다. 실제 음성 인식, Google 로그인·동기화, 처음 여는 문서 처리까지 오프라인 동작을 보장하지 않습니다. 서비스 워커는 앱 자체 파일만 캐시하며 Google 응답·토큰·사용자 문서를 캐시하지 않습니다.
- 실제 Google 로그인에는 앱 소유자가 생성한 공개 웹 OAuth 클라이언트 ID가 필요합니다. `google-config.js`의 기본값은 비어 있으며 **현재 실계정 연동은 설정 전 상태**입니다. [Google 설정 안내](GOOGLE_SETUP.md)를 확인하세요. ID를 전달받으면 이 공개 설정을 배포할 수 있습니다. 보안 비밀번호는 사용하지 않습니다.
- 같은 Google 계정의 기본 캘린더에 이 앱으로 등록한 단발 일정을 기기 간 등록·수정·삭제·새로고침합니다. 모든 Google 일정을 읽는 앱은 아닙니다. 실제 사용자 Google 로그인과 기기 검증은 OAuth 설정 후 수행해야 합니다.
- 연결 토큰은 메모리에만 유지하고 만료 또는 창 종료 후 재연결합니다. 화면을 보는 동안 1분 간격·화면 복귀 시 불러옵니다. 기기 초안을 확인하고 등록 버튼을 눌러야 Google에 저장됩니다. 음성 인식 직후 미확인 내용을 Google에 자동 전송하지 않습니다.
- 중복 요청은 동일 원격 ID로 확인하며, ETag로 다른 기기의 수정과 충돌을 검사합니다. 다른 계정의 기존 일정을 저장하지 않습니다. Google 등록 일정 삭제는 확인 후 원격에도 반영됩니다. 기기 목록 비우기와 연결 해제는 Google 일정을 삭제하지 않습니다.
- 잠금화면은 OS의 캘린더 알림·위젯을 사용자 본인이 켜야 합니다. 웹 앱이 잠금화면에 자체 위젯을 강제로 설치하거나 하루 전체 목록 표시를 보장하지 않습니다. 앱의 설정 안내에서 iOS·안드로이드 절차를 확인하세요.
